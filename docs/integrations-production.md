# Подключение сервисов для study.shkolaru.ru

Продолжение [инструкции запуска на сервере](launch-shkolaru.md). Все значения
ниже записываются на VPS в `/opt/emil2/.env.production`, а не в текст урока
или публичный GitHub. Админка «Интеграции» показывает режим работы без
раскрытия ключей. Кнопок выдачи ключей сторонних сервисов в ней нет.

Примеры с `<...>` нужно заменить данными выбранного поставщика; это не
готовые рабочие ключи. Реальные сервисы оплачиваются по их тарифам.

| Сервис             | Нужен для первого production-запуска | Где взять данные                                   |
| ------------------ | ------------------------------------ | -------------------------------------------------- |
| SMTP               | Да                                   | Личный кабинет почтового сервиса, раздел SMTP      |
| Чат и embeddings   | Да                                   | Личный кабинет API-провайдера моделей              |
| S3-файлы           | Да                                   | Облачное хранилище и ключ сервисной учётной записи |
| S3-копии           | До приглашения учеников              | Отдельный закрытый бакет и ключ для копий          |
| ЮKassa             | Да, сначала тестовый магазин         | Кабинет магазина → API и уведомления               |
| Telegram           | Нет                                  | Официальный `@BotFather` в Telegram                |
| Метрика            | Нет                                  | Созданный вами счётчик Яндекс Метрики              |
| Sentry / GlitchTip | Нет                                  | Проект мониторинга → клиентский DSN                |

Текущий production-режим требует SMTP, реальный API моделей, S3 и
провайдера ЮKassa. Для разработки без этих подключений есть локальный
просмотр на Mac с тестовыми ответами и оплатой без денег. Наличие ключа
проходит проверку конфигурации, но его действительность проверяется сценарием
после запуска.

## 1. Почта: ссылки для входа

1. Выберите почтовый сервис с исходящим SMTP и возможностью отправки от
   вашего домена. Обычный пароль от почты иногда не подходит: сервис выдаёт
   отдельный пароль приложения или SMTP-ключ.
2. Подтвердите домен `shkolaru.ru` по инструкции сервиса. Он покажет DNS-записи
   SPF и DKIM; добавьте их в DNS-зону. Если SPF уже есть, объедините разрешения
   по инструкции поставщика: две разные SPF-записи для одного имени неверны.
   MX существующей входящей почты не меняйте без необходимости.
3. Подтвердите адрес отправителя, например `no-reply@shkolaru.ru`. Это только
   пример: сначала создайте/подтвердите его у поставщика. Укажите действующий
   отдельный адрес поддержки в `SUPPORT_EMAIL`.
4. В конфигурации заполните:

```dotenv
MAIL_TRANSPORT=smtp
SMTP_HOST=<сервер SMTP от поставщика>
SMTP_PORT=465
SMTP_USER=<логин SMTP>
SMTP_PASSWORD='<пароль приложения или SMTP-ключ>'
MAIL_FROM="Эмаль <no-reply@shkolaru.ru>"
```

Используйте именно порт, который выдал поставщик: **465 — TLS**, **587 —
STARTTLS**. На рабочем сервере незашифрованная отправка не допускается.
Если в секрете есть `$` или `#`, одинарные кавычки в файле Compose сохраняют
его буквально; не добавляйте комментарий в строку значения. Если сам секрет
содержит кавычку, применяйте правила dotenv/Compose поставщика, а не меняйте
секрет наугад.

После запуска откройте `/login`, запросите ссылку на свой настоящий ящик.
Письмо должно прийти с выбранным отправителем; ссылка должна начинаться с
`https://study.shkolaru.ru`. Пройдите её в том же браузере, где запросили вход.
Проверьте папку «Спам», лимит отправки и доступность SMTP из сети VPS, если
письма нет. Mailpit используется только в локальном просмотре, для настоящих
учеников он не доставляет письма.

## 2. ИИ: ответы и поиск — два разных назначения

Подписка на веб-чат нейросети обычно **не включает API**. Нужны API-аккаунт,
баланс, ключ и точные имена доступных моделей. Не все сервисы с похожим
чатом совместимы с этим приложением.

Для самого простого подключения выберите API, который поддерживает
OpenAI-совместимые **потоковый чат и embeddings**. Получите у поставщика:

- базовый HTTPS-адрес API (часто заканчивается на `/v1`, без `/chat/completions`);
- имя чат-модели;
- имя embeddings-модели, выдающей **1536 чисел** на текст;
- ключ и условия обработки данных/размещения сервиса.

```dotenv
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=<базовый HTTPS-адрес API>
LLM_API_KEY='<секретный ключ>'
LLM_CHAT_MODEL=<точное имя чат-модели>
LLM_EMBEDDING_MODEL=<точное имя модели embeddings>
EMBEDDING_DIM=1536
LLM_TEMPERATURE=0.2
LLM_DAILY_BUDGET_RUB=1000
```

Последнее число — настраиваемый дневной бюджет приложения, а не обещанная
стоимость: сопоставьте его со своим бюджетом, тарифами и биллингом поставщика.
Установите также лимит расходов в кабинете провайдера. Лимиты запросов
ученика настраиваются в **«Настройки → Тарифы»**.

Если embeddings предоставляет другой сервис, отдельно заполните
`LLM_EMBEDDING_BASE_URL` и `LLM_EMBEDDING_API_KEY`. Для провайдера
`LLM_PROVIDER=anthropic` эти два поля обязательны: Anthropic используется
для чата, а embeddings запрашиваются у отдельного совместимого сервиса.
Размерность существующей базы — 1536; смена одной переменной на другое
число не перестраивает базу и поисковый индекс.

**Как проверить:** опубликуйте проверенный урок с источниками, дайте worker
время построить поиск и задайте тьютору вопрос по его содержанию. В ответе
должны быть ссылки на доступные фрагменты. Задайте вопрос вне материалов:
система должна обозначить отсутствие опоры. Проверьте объяснение ошибки
в задании. Медицинскую корректность оценивает преподаватель.

Промпты обычного тьютора уже предусмотрены в коде. Для проверки выбора
ответов промпт **не нужен**: работает сравнение с эталоном автора. В
редакторе есть отдельный шаблон дополнительной ИИ-рецензии, который можно
скопировать и использовать вручную. Его результат не ставит отметку
эксперта и не публикует урок автоматически. Общий редактор промптов в
настройках пока не реализован. Подробности: [tutor.md](tutor.md).

## 3. S3: изображения, импорт и копии

S3 — хранилище файлов отдельно от сервера. «Бакет» означает отдельный
контейнер файлов в кабинете облачного поставщика. Приложение поддерживает
S3-совместимый HTTPS API, например Object Storage в российском регионе.
Само наличие слова S3 в тарифе ещё не гарантирует поддержку версий и
условной записи, которые использует проект.

1. Создайте **два закрытых бакета** в одном поддерживаемом облаке и регионе:
   один для файлов проекта, второй для резервных копий. Их имена должны
   отличаться. Выберите доступные имена; не копируйте чужое имя из примера.
2. Включите **версионирование** рабочего бакета до загрузки материалов.
   Примените правила из
   [app-bucket-lifecycle.json](../infra/production/app-bucket-lifecycle.json):
   они сохраняют активные файлы и удерживают прежние версии 14 дней.
3. Для backup-бакета примените
   [backup-lifecycle.json](../infra/production/backup-lifecycle.json),
   срок хранения — 14 дней. В интерфейсе провайдера правила можно создать
   вручную с теми же условиями. Не назначайте удаление активных файлов
   рабочего бакета через 14 дней.
4. Создайте сервисную учётную запись и S3 access key / secret key с правами
   чтения, записи и удаления файлов **только рабочего бакета**. Второй ключ
   должен читать список/версии рабочего бакета и писать/читать файлы
   backup-бакета для копирования и восстановления. Настройка ролей отличается
   у поставщиков; проверяйте фактическую область доступа, не выдавайте права
   администратора всего облака.
5. Запишите endpoint, регион, имена бакетов и ключи:

```dotenv
STORAGE_DRIVER=s3
S3_ENDPOINT=https://storage.yandexcloud.net
S3_REGION=ru-central1
S3_BUCKET=<имя закрытого рабочего бакета>
S3_ACCESS_KEY=<ключ приложения>
S3_SECRET_KEY='<секрет приложения>'
BACKUP_S3_ENDPOINT=https://storage.yandexcloud.net
BACKUP_S3_REGION=ru-central1
BACKUP_S3_BUCKET=<имя отдельного закрытого backup-бакета>
BACKUP_S3_ACCESS_KEY=<ключ резервного копирования>
BACKUP_S3_SECRET_KEY='<секрет резервного копирования>'
```

Здесь endpoint и регион — пример для Yandex Object Storage. Для другого
сервиса замените оба набора согласованно. В текущей процедуре копирования
рабочий и backup-бакеты должны быть в одном сервисе/регионе с поддержкой
копирования версий. Документация примера:
<https://yandex.cloud/ru/docs/storage/>.

**Не включайте публичное чтение и не публикуйте бакет как сайт.** Картинки
отдаются через защищённый маршрут приложения с проверкой доступа к уроку;
настраивать публичный CORS для браузерной загрузки не требуется.

Проверка: загрузите картинку из редактора, сохраните урок, перезагрузите
страницу и проверьте изображение в студенческом просмотре. Для платного
урока проверьте отказ без доступа. Затем запустите резервное копирование
из основной инструкции и найдите завершённый префикс с `COMPLETE.json`
в другом бакете. Перенос старых файлов с Mac описан отдельно в разделе 11
[инструкции запуска](launch-shkolaru.md).

## 4. ЮKassa: сначала тестовая оплата

1. Создайте магазин и получите доступ к **тестовому режиму** у ЮKassa.
   Сохраните тестовые shopId и секретный API-ключ. Для настоящего приёма
   денег требуется оформление магазина по правилам ЮKassa.
2. Настройте HTTP-уведомления по адресу:

   **`https://study.shkolaru.ru/api/webhooks/yookassa`**

3. Включите события **`payment.succeeded`**, **`payment.canceled`**,
   **`refund.succeeded`**. URL должен быть доступен по HTTPS после запуска.
4. В актуальной официальной документации ЮKassa возьмите список IP/CIDR
   для входящих уведомлений. Запишите их через запятую, без пояснений,
   в `YOOKASSA_WEBHOOK_IPS`. Не подставляйте IP своего VPS или случайный
   диапазон «разрешить всех».
5. Уточните код ставки НДС для чека и, при необходимости, код системы
   налогообложения с бухгалтером/по настройкам магазина. Это данные вашего
   бизнеса; проект не выбирает их за владельца.

```dotenv
PAYMENTS_PROVIDER=yookassa
YOOKASSA_TEST_MODE=true
YOOKASSA_SHOP_ID=<ID тестового магазина>
YOOKASSA_SECRET_KEY='<тестовый API-ключ>'
YOOKASSA_WEBHOOK_IPS=<официальные IP и CIDR через запятую>
RECEIPT_VAT_CODE=<согласованный код ставки НДС>
RECEIPT_TAX_SYSTEM_CODE=<код СНО, если требуется магазину>
```

Справочник и актуальные тестовые карты:
<https://yookassa.ru/developers>. Порядок проверок проекта:
[billing.md](billing.md).

После запуска зайдите учеником, выберите тариф и оплатите **тестовой картой
из документации**. Доступ должен появиться после подтверждения платежа
сервером. Проверьте отказ оплаты, отмену автопродления и тестовый возврат
в кабинете администратора. Сверьте статусы с тестовым кабинетом ЮKassa.
Флаг `YOOKASSA_TEST_MODE=true` не заменяет тестовые ключи: используйте их вместе.

Переход к реальным деньгам — отдельный шаг после приёмки: реальные ключи,
`YOOKASSA_TEST_MODE=false`, уведомления рабочего магазина, согласованные
чеки, цены и оферта. Автоматически этот переход не выполняется. Тестовые
подписки/сохранённые способы оплаты нельзя считать рабочими: перед сменой
магазина проверьте их и отключите тестовые автопродления.

## 5. Telegram: дополнительный вход

1. Откройте официальный `@BotFather` в Telegram и выполните `/newbot`.
   Задайте имя и уникальное имя бота, заканчивающееся на `bot`.
2. Выполните `/setdomain`, выберите созданного бота и отправьте
   **`study.shkolaru.ru`**, без `https://` и без пути.
3. Сохраните выданный токен и имя бота в файле:

```dotenv
TELEGRAM_BOT_TOKEN='<токен от BotFather>'
TELEGRAM_BOT_USERNAME=<имя бота без символа @>
```

Оба поля заполняются вместе. Чтобы отложить подключение, оставьте **оба
пустыми**. После применения конфигурации проверьте Telegram-вход на самом
HTTPS-домене в отдельном профиле браузера; также проверьте привязку к
существующему аккаунту в профиле. Если домен меняется, измените его и в
BotFather. Не отправляйте токен ученикам.

Это **Telegram Login Widget** для входа/привязки. Webhook Telegram здесь
настраивать не требуется. Отдельный бот-тьютор и отправка напоминаний в
Telegram пока не реализованы. Почтовый вход остаётся самостоятельным способом.

## 6. Метрика и мониторинг — по желанию

**Яндекс Метрика:** создайте счётчик для `https://study.shkolaru.ru`, возьмите
его числовой ID и запишите `YANDEX_METRIKA_ID=число`. Если аналитика пока
не нужна, оставьте значение пустым. Ввод слов вместо числа остановит проверку
конфигурации. Скрипт учитывает согласие пользователя; Вебвизор отключён.
Проверьте загрузку после согласия и отсутствие до него.

**Sentry / GlitchTip:** создайте проект, получите HTTPS DSN клиента и запишите
его в `SENTRY_DSN`. Это не управляющий API-токен. Пустое поле отключает
отправку. Встроенный транспорт очищает служебные события от персональных
данных; не подключайте дополнительные плагины записи сессий без отдельной
оценки. Подготовьте уведомления об ошибках и отдельно об ошибках backup-service.

## 7. Применить изменения и проверить

Из `/opt/emil2` на сервере:

```bash
docker compose --env-file .env.production -f docker-compose.production.yml run --rm --no-deps --entrypoint node web --import tsx scripts/ops/preflight.ts
docker compose --env-file .env.production -f docker-compose.production.yml up -d web worker caddy
curl -f https://study.shkolaru.ru/api/health
```

Для первого запуска сначала выполните сборку и миграции из основной
инструкции. При последующих изменениях окружения `up -d` пересоздаёт
затронутые контейнеры; обычный `restart` новые значения файла не применяет.
После замены ключей проверьте соответствующий сценарий, не только значок
«настроено» в админке. Успешный `/api/health` подтверждает сайт, базу и worker,
но сам по себе не проверяет доставку писем, списание/возврат или качество ИИ.
