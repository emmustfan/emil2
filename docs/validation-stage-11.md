## Блокировки

- Единые функции и порядок захвата находятся в [locks.ts](../lib/content/locks.ts).
  Учащиеся разделяют `content:topic:<id>`, писатель берёт сначала
  `topic:<id>`, затем тот же ключ данных эксклюзивно. Действия одного
  учащегося по-прежнему сериализованы через `learning:<actor>`.
- [Интеграционные проверки](../tests/integration/stage11.test.ts) удерживают
  транзакцию первого ученика открытой, пока второй завершает ответ.
  Ожидание публикации подтверждается через `pg_blocking_pids`, затем
  транзакция освобождается; ответ с прежней версией получает 409.
  Проверок через sleep или предполагаемую длительность запроса нет.
- Вызов shared-helper подтверждён spy при исполнении загрузки урока,
  ответа на пропуск, начала/ответа теста, раскрытия/оценки SRS,
  области тьютора, действий/представления демо и переноса гостевых данных.

## Совместимость и сохранность данных

- SQL-миграций нет. Нормализация выполняется при записи/импорте. Read-only
  DTO закрепляет ключи существующих пропусков до первого редактирования,
  не меняя базу при открытии. Чисто служебная запись ID не снимает публикацию.
- Проверена заполненная синтетическая база: опубликованный legacy-урок,
  `Gap`, первый `GapAnswer`, `Card`, `ReviewLog` и `TopicProgress`.
  После изменения формулировки сохраняются `Gap.id`, ответ, карточка
  и весь прогресс. Смена отвлекающего варианта не сбрасывает карточку.
- Смена эталона или допустимых формулировок сбрасывает карточку в `NEW`
  с немедленным сроком. Снимок первого ответа, журнал и прогресс остаются.
  Перестановка правильных вариантов и эквивалентные текстовые ответы
  не вызывают сброса. Прежний выбор отображается даже после удаления варианта.
- Повторная публикация, архивирование/возврат пропуска и прежний API без ID
  проверяются существующими интеграционными сценариями без их ослабления.
  Импорт проверяет наличие короткого ID у каждого нового пропуска.

## Парсер и редактор

- [Модульные проверки](../tests/unit/stable-gaps.test.ts): правка контекста,
  перестановка, legacy-ключи, копии, коллизии, допустимые/недопустимые ID,
  сохранение настроек, таблицы и игнорируемая разметка, round-trip TipTap,
  правка вариантов, отсутствие служебного ID в студенческих блоках.
- Браузер проверяет сохранение ID через окно вариантов и перезагрузку,
  копирование задания, принятие исправленного текста/настроек из ответа
  сервера, публикацию и прохождение урока. Старые проверки исходника
  адаптированы только к префиксу ID; текст, версии, ответы и права проверяются.

Используются только тестовые адаптеры и собственные синтетические записи.
Медицинские материалы не менялись, внешние сервисы и публичный сайт
не подключались. Порядок выпуска опубликованного черновика остаётся
прежним до этапа 12.
