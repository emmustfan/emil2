# ИИ-тьютор: просмотр и настройка

## Что попробовать на Mac

1. Запустите обновлённый проект командой `bash start-mac.command`. Она поднимает
   сайт и worker. После первого запуска подождите несколько секунд, пока
   подготовятся материалы для тьютора.
2. Откройте http://localhost:3000/learn/platform-demo/answer-types.
   Внизу урока найдите «ИИ-тьютор» и спросите: «Сколько дней в неделе?».
3. Нажмите «Задать вопрос». В ответе появится сноска `[1]`; нажатие переводит
   к подсвеченному блоку методички. Под ответом есть источники и оценка
   «Полезно» / «Неточно».
4. Спросите о космическом двигателе. Ответ начнётся с «В материалах платформы
   этого нет». Система не придумывает источник.
5. Впишите в вопрос телефон — отправка будет заблокирована с подсказкой убрать
   персональные данные. Не используйте данные реальных пациентов.
6. Ошибитесь в пропуске или вопросе теста. Кнопка «Объяснить · ИИ» отправляет
   сохранённое задание и ваш ответ; вручную переписывать их не нужно.
7. Гостю доступно пять вопросов в этом браузере. После входа через `/login`
   доступны личный дневной лимит и http://localhost:3000/tutor с выбором предмета.
   Для локального аккаунта `owner@example.ru` письмо попадает в Mailpit на порту 8025.

В локальном preview всегда используется **тестовая модель** без внешних запросов.
Она выбирает короткие фрагменты найденных материалов и добавляет сноски;
полноценные формулировки и качество медицинских объяснений требуют реальной модели.
Проверенные опубликованные примеры остаются немедицинскими, медицинский seed —
черновиками. Текущий диалог виден до перезагрузки/смены предмета; экран истории
диалогов относится к P1 и пока не реализован.

Если материалы ещё готовятся, повторите вопрос через минуту: такой запрос
не расходует лимит. При тайм-ауте или ошибке генерации лимит возвращается.
Повтор той же неудачной отправки через «Повторить вопрос» не списывает вопрос
дважды. Гостевые вопросы не переносятся в аккаунт до этапа демо-воронки.

## Как устроен поиск

- `content-index` обрабатывает отдельный worker. Чанки группируются по заголовку,
  ориентир — 500 токенов, верхняя граница — 800; оценка длины — примерно 4 символа
  на токен. Короткие темы могут давать меньший чанк. Пропуски разворачиваются
  в опубликованные правильные ответы, включая множественные наборы.
- Индекс хранит версию темы и идентичность embedding-модели/endpoint. Устаревшие
  версии не участвуют в поиске; переиндексация заменяет чанки одной транзакцией.
- Косинусный поиск выполняет PostgreSQL/pgvector с HNSW-индексом. Кандидаты
  ранжируются с бонусом текущей теме. Тестовая модель дополнительно проверяет
  совпадение слов; её хеш-векторы не заменяют семантические эмбеддинги.
- Гость ищет только в текущей бесплатной теме. Вошедший — в бесплатных темах
  выбранного предмета и материалах, открытых через `hasAccess`. Черновики,
  снятые с публикации предметы и старые версии исключены.
- Если подходящих фрагментов нет, сервер возвращает фиксированный ответ
  без сносок и без вызова внешней модели. Это консервативный вариант MVP.

## Лимиты и данные

Дневной лимит берётся из `Plan.tutorDailyLimit`: по seed 15 для бесплатного
аккаунта, 150 для подписки. При нескольких действующих подписках используется
наибольшее значение. Ручной доступ даёт платный лимит из `AppSetting`.
Лимит общий для предметов; сутки определяет часовой пояс профиля. Гостевой
лимит — `tutor.demoLimit`, без ежедневного сброса. Дополнительно действует
`tutor.requestsPerMinute` (10) на актёра. Тайм-аут — `tutor.timeoutMs` (60 секунд).

Запросы, ответы, источники, модель, доступные счётчики токенов, задержка и оценка
сохраняются в TutorConversation/TutorMessage. Для mock число токенов оценочное;
для HTTP используется usage провайдера, при его отсутствии — null.
Частичный неудачный ответ не записывается как готовый. После аварийной остановки
резерв восстанавливается при следующем запросе/чтении лимита по истечении lease.

В модель не передаются профиль, id, email и имя пользователя. Распространённые
форматы телефона, email, СНИЛС, паспорта и даты рождения блокируются регулярными
выражениями; контактные данные в индексируемом тексте редактируются. Это
эвристический фильтр, а не полноценное обезличивание произвольного текста.

## Реальный LLM для разработчика

В этой облачной сессии реальные LLM не вызывались. HTTP-адаптеры проверены
подменёнными ответами; для подключения нужны ваши настройки в локальном `.env`.
Значения ключей не помещайте в Git или чат.

Для OpenAI-совместимого API: `LLM_PROVIDER=openai_compatible`, `LLM_BASE_URL`
с путём API, например `https://your-gateway.example/v1`, `LLM_API_KEY`,
`LLM_CHAT_MODEL`, `LLM_EMBEDDING_MODEL`, `LLM_TEMPERATURE`.
Сервис должен поддерживать `/chat/completions` со стримом и `/embeddings`.

Для Anthropic: `LLM_PROVIDER=anthropic`, `LLM_API_KEY`, `LLM_CHAT_MODEL`;
`LLM_BASE_URL` необязателен, по умолчанию `https://api.anthropic.com/v1`.
Anthropic не выдаёт эмбеддинги: отдельно обязательны OpenAI-совместимые
`LLM_EMBEDDING_BASE_URL`, `LLM_EMBEDDING_API_KEY`, `LLM_EMBEDDING_MODEL`.

`EMBEDDING_DIM` для текущей базы должен быть **1536**. Для другой размерности
потребуется отдельная миграция vector-колонки и HNSW-индекса. После смены модели
или endpoint перезапустите worker: старые несовместимые чанки скрываются,
актуальные опубликованные темы индексируются заново.

Mac-preview принудительно оставляет mock независимо от `.env`. Для разработки
с выбранным API используйте основной Compose или хостовые `pnpm dev` и
`pnpm worker`. Производственные платёжный/S3-адаптеры и полная эксплуатационная
подготовка относятся к следующим этапам. Перед реальным учебным запуском
нужна отдельная оценка качества модели на вопросах с участием эксперта.
