# Прогресс студентов и ответы

## Журнал группы

1. Войдите преподавателем и откройте «Учебные группы». В меню администратора
   этот пункт называется «Группы и прогресс».
2. В строке группы выберите **«Журнал»** нужного предмета. В списке групп
   видны число зачисленных, число заявок и средняя доля завершённых тем
   по каждому доступному предмету. Заявки открываются на странице группы.
3. В журнале выберите раздел, включите **«Только отстающие»** или
   **«Показать исключённых»**, затем нажмите «Показать». Пороги задаются
   в настройках прогресса. Итоги студента и отставание рассчитываются
   по всему предмету. Итоги темы учитывают студентов, видимых после фильтрации,
   за исключением обезличенных записей.
4. В ячейке видны статус темы, доля верных первых ответов, лучший тест и
   учёт просмотра видео. Наведение на ячейку показывает подробности. Имя
   студента открывает карточку с ФИО, группой и номером зачётки.
5. Нажмите **«Анализ заданий»**, чтобы увидеть число ответивших, долю верных
   первых ответов и до трёх частых ошибок по заданию. Учитываются действующие
   зачисления. Ссылка на редактор появляется у сотрудников с правом
   редактировать этот предмет.
6. **«Скачать CSV»** выгружает текущие строки и темы. Файл использует UTF‑8
   с BOM и разделитель `;` для Excel. Кнопка доступна, когда есть строки
   для выгрузки.

Преподаватель видит назначенные ему пары «группа + предмет», заведующий —
группы по предметам своей кафедры, администратор факультета — предметы групп
своего факультета. Администратору платформы доступны все пары. Данные за
пределами области недоступны, включая прямые ссылки и экспорт.

Просмотр карточки и выгрузка записывают в журнал доступа сотрудника, студента,
группу, предмет и время. При экспорте создаётся запись по каждой строке
студента. Режим входа от имени пользователя закрывает доступ к этим данным.

## Открыть административную сводку

Административная сводка и карточка по всем предметам доступны только
администратору платформы.

1. Войдите администратором и выберите слева **«Прогресс студентов»**.
2. Найдите ученика по имени или email. В списке только пользователи с ролью
   «Ученик», которые не удалены; заблокированные ученики остаются в истории.
3. Выберите **«Отстающие»**, чтобы увидеть тех, кто завершил меньше заданного
   процента тем по предметам с активностью **или** не занимался больше
   заданного числа дней. По умолчанию это 50% и 7 дней. Пороги и размер
   страницы меняются в «Настройки».
4. Нажмите заголовок столбца, чтобы изменить сортировку; повторное нажатие
   меняет направление. Доступны все столбцы, включая предметы и даты.
5. Нажмите имя ученика. Ссылка **«Прогресс и ответы»** также есть в списке
   пользователей и в карточке пользователя.

«Средний балл» — среднее лучших результатов тестов по изученным опубликованным
и проверенным темам. Это тот же принцип, что в собственном кабинете ученика.
В знаменателе завершения — опубликованные проверенные темы предметов,
по которым у ученика уже есть активность. Темы, с которыми он ещё не
знакомился в других предметах, автоматически в знаменатель не добавляются.

## Карточка ученика

В административной карточке можно выбрать один предмет или все предметы.
Карточка из группы ограничена предметом журнала. При административном
просмотре всех предметов поле предмета в записи аудита пустое.

В карточке находятся:

- завершённые темы, средний балл и последняя активность;
- по каждой теме — первый ответ на каждый пропуск, текущий правильный ответ,
  все сохранённые попытки с датами и отметкой «Практика»;
- прогоны тестов темы, баллы, продолжительность, ответы ученика и эталоны;
- видео с измеренной долей просмотра, если известна длительность, способом
  учёта, отметкой о завершении и ответами на вопросы в видео;
- количество карточек всего, к повторению и просроченных;
- распределение оценок «Сложно / Нормально / Легко» за последние 30 календарных
  дней с подписью **«Самооценка студента»**;
- полоса активности за 30 дней: открытия уроков, ответы на пропуски,
  просмотры видео, старты тестов, ответы в тестах, оценки карточек и вопросы тьютору;
- только количество вопросов тьютору, по темам. **Переписка не показывается.**

«К повторению» включает доступные карточки, срок которых уже наступил,
без суточного ограничения на новые карточки. «Просрочено» — те из них,
которые нужно было повторить до начала сегодняшнего дня по времени ученика.
Время попыток в карточке показывается в часовом поясе сотрудника.
Дни полосы активности указаны в UTC.

У ответов к другой опубликованной версии есть пометка **«Ответ к версии N»**.
Эталон восстанавливается из сохранённого снимка публикации. Если старый
снимок отсутствует, вместо предполагаемого старого эталона показано
«Эталон прежней версии недоступен». Первый ответ и его оценка остаются
неизменными при тренировке и публикации новых формулировок.

В группе удалённый ученик отображается как **«Удалённый пользователь»**
при включении показа исключённых. Имя, контакты, номер зачётки и ответы
скрыты с момента запроса удаления. При анонимизации активная или бывшая
запись о зачислении остаётся со статусом «Исключён». Учебная история
удаляется по обычной процедуре, записи доступа сохраняются.

## Что видит ученик

В кабинете у зачисленного предмета ссылка **«Что видит преподаватель»**
открывает действующее уведомление группы.

В открытом уроке авторизованный ученик раскрывает **«История ответов»**.
Там только его попытки по пропускам, включая практику, время, результат
и номер версии. История не раскрывает эталоны ещё не отвеченных заданий.
Гостевые ответы в новый журнал всех попыток не записываются; прежнее
сохранение первого гостевого ответа продолжает работать.

В этапе 12А старые первые ответы авторизованных пользователей скопированы
в журнал с прежними датами. Для этих попыток указана версия темы на момент
переноса. Этап 16 использует существующие записи попыток.

## Демо на Mac

После `bash start-mac.command` в preview появляются 12 вымышленных учеников.
Их имена начинаются с «Демо» и заканчиваются «(демо)», email —
`demo-student-01@example.ru` … `demo-student-12@example.ru`.

Есть два отличника, четыре средних ученика, два отстающих, два давно
не занимавшихся, один новичок и один ученик с повторными ошибками в практике.
История распределена по последним 30 дням и создаётся настоящими сервисами
обучения. Для платных уроков выдан ручной доступ с причиной «демо».

Первые три аккаунта готовы к входу через Mailpit. Например, откройте отдельный
браузер, запросите вход для `demo-student-01@example.ru` и откройте письмо
в http://localhost:8025 в том же браузере, где начинали вход.

В демо есть отдельная опубликованная preview-копия стоматологического урока.
Она явно помечена как непроверенный медицинский пример, не получает
экспертного подтверждения и не входит в оценочные итоги кабинета.
Исходный авторский стоматологический черновик сохраняется. Такая копия
и демо-ученики создаются только на preview-базе, вне production; обычный
`pnpm db:seed` их не создаёт.

Повторный запуск сохраняет ручные изменения имени, email, ролей и учебных
данных: ученик с любой существующей активностью пропускается. Если первый
запуск был прерван посреди ученика, уже созданная активность также сохраняется
и не переписывается автоматически.

## Проверка на preview

- Под `teacher@example.ru` после входа откройте
  [«Группы и прогресс»](http://localhost:3000/teacher/groups). В **«Демо-группе 101»**
  выберите журнал «Знакомство с обучением» либо «Попробуйте платформу». В «Знакомстве с обучением»
  можно сравнить попытки и итоги разных студентов. В «Попробуйте платформу»
  откройте тестовую видеолекцию отдельным аккаунтом зачисленного демо-студента,
  отметьте просмотр и вернитесь в журнал преподавателя.
- Под `owner@example.ru` доступны «Группы и прогресс» и административная
  сводка «Прогресс студентов». Для раздельных входов используйте разные
  профили браузера и [Mailpit](http://localhost:8025).

### Нагрузочный замер

Скрипт создаёт отдельную синтетическую группу с 40 студентами и 80 темами.
После первого входа преподавателя соберите preview и запустите отдельный
сервер замера в контейнере. Обычный preview остаётся доступен на порту 3000.

```bash
docker compose -f docker-compose.yml -f docker-compose.preview.yml exec web sh -c 'pnpm build && NODE_ENV=test APP_URL=http://localhost:3116 pnpm start --port 3116'
```

В другом окне Terminal запустите замер из той же папки.

```bash
docker compose -f docker-compose.yml -f docker-compose.preview.yml exec -e APP_URL=http://localhost:3116 web pnpm exec tsx scripts/preview/teacher-demo.ts --measure
```

Без `--measure` скрипт только загружает фикстуру и выводит путь к журналу.
Повторный запуск использует созданную фикстуру. Скрипт разрешён только
на preview-базе вне production. Замер читает полную серверную страницу
по локальному HTTP, делает три прогрева и 25 последовательных запросов
для журнала и карточки. Цели p95 — соответственно 1 000 и 700 мс.
