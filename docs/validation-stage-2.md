## Проверенные сценарии

- Редактор через интерфейс создаёт предмет, раздел и тему с 10 пропусками,
  добавляет 5 вопросов, указывает автора/рецензента/источники, отмечает проверку
  и публикует. Повторная публикация сохраняет ID и не создаёт вторую версию.
- Ошибка `[[ответ|]]` показывает номер строки и блокирует публикацию; черновик
  при этом сохраняется и открывается после перезагрузки.
- Два редактора не перезаписывают друг друга: устаревший editRevision даёт 409,
  локальный текст остаётся в поле, дальнейшая запись блокируется до обновления.
- Неизменившиеся пропуски сохраняют ID и ответы; исчезнувшие архивируются,
  карточки приостанавливаются. Возвращённый пропуск получает прежний ID.
- Вопрос с попытками архивируется, его карточки приостанавливаются, история
  ответов сохраняется. Удаление темы с прогрессом откатывается целиком.
- Ошибка очереди откатывает публикацию и создание пропусков. Задача pg-boss
  записывается в той же транзакции, что статус/версия темы.
- Таблицы GFM поддерживают пропуски с обычными и экранированными `|`.
  Code/inlineCode и экранированные скобки не создают пропусков.
- XSS/iframe/unsafe URL удаляются из превью; HTML не исполняется.
- USER не получает данные/ответы из административных API, EDITOR допускается;
  Origin проверяется у всех записывающих операций. Проверены безопасный CRUD,
  поиск, пагинация и сохранение ошибочного черновика.

Для чистой БД выполнены все четыре миграции, seed дважды с проверкой ID, затем
симулированы редакторская правка/удаление пропуска/архивация вопроса/смена цены.
Повторный seed сохранил эти изменения. Временная БД после проверки удалена;
реальные пользовательские материалы не изменялись.

Проверен и обновлённый Compose: `migrate` завершился с кодом 0, web/worker
запущены, `/api/health` отвечает 200 с `database: ok`, административный API
отклоняет гостя с 401, worker выполняет smoke-задачу.

## Ручная проверка

1. Добавить свою почту в `ADMIN_EMAILS` локального `.env`, выполнить `pnpm db:seed`
   и войти по письму. Сам seed не подтверждает почту и не создаёт сессию.
2. Открыть `/admin`, создать предмет и установить ему статус «Опубликовано».
3. Создать раздел и тему; ввести Markdown с 10 пропусками и добавить 5 вопросов.
4. Проверить автосохранение и превью, намеренно испортить пропуск и увидеть
   номер строки. Исправить текст, указать автора, рецензента и источники.
5. Отметить «Проверено экспертом», отправить на проверку и опубликовать.
6. Открыть вторую вкладку и проверить предупреждение при конфликтующем сохранении.

Проверку экспертной отметки в автоматических тестах проходят только синтетические
материалы, не клинический контент. Демо-темы seed остаются DRAFT/needsExpertReview.
