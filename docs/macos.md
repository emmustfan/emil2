# Запуск на Mac

Для просмотра нужен Docker Desktop; Node.js и pnpm на Mac устанавливать
необязательно — они работают внутри контейнеров. Codex можно открыть в этой
папке для дальнейшей разработки, но для самого просмотра он не нужен.

## Установка и запуск

1. Установите [Docker Desktop для Mac](https://www.docker.com/products/docker-desktop/).
   Выберите Apple Silicon для M1/M2/M3/M4/M5 либо Intel для Mac с процессором Intel.
2. Откройте Docker Desktop и дождитесь готовности Docker Engine.
3. Скопируйте **текущую полную папку проекта** на Mac. В ней должны быть
   `package.json`, `app`, `prisma`, `docker-compose.yml` и `start-mac.command`.
   В исходном начальном коммите Git этих файлов не было.
4. Откройте Terminal и перейдите в папку проекта. Можно ввести `cd ` с пробелом
   и перетащить папку из Finder в окно Terminal, затем нажать Enter.
5. Выполните:

   ```sh
   bash start-mac.command
   ```

   Первый запуск загружает образы и собирает проект; потребуется несколько минут.
   Скрипт создаёт `.env` из примера только при его отсутствии. Данные повторным
   запуском не удаляются. После готовности откроется браузер.

Адрес сайта: **http://localhost:3000/subjects**. Здесь localhost относится уже
к вашему Mac и доступен обычному браузеру.

## Что посмотреть

- Предмет «Попробуйте платформу» → бесплатная тема «Как учиться на платформе».
  В ней 10 пропусков и тест из 5 вопросов. Попробуйте ошибиться, обновить страницу
  и пройти тест повторно.
- Бесплатная тема «Три типа ответа: попробуйте сами» показывает одиночный выбор,
  чекбоксы и ввод текста.
- Соседняя закрытая тема показывает ограничение доступа. Настоящей оплаты нет.
- Для редактора откройте http://localhost:3000/login и запросите вход для
  `owner@example.ru`. Письмо попадёт только в локальный Mailpit:
  **http://localhost:8025**. Скопируйте ссылку из письма в тот же браузер,
  где запрашивали вход, подтвердите вход и заполните onboarding. После этого
  доступна http://localhost:3000/admin. Это локальный тестовый аккаунт.

Просмотр использует отдельный Compose-проект `emil2-local-preview`, собственные
тома и базу `dental_preview_000000000001`. Медицинские seed-темы остаются
непроверенными черновиками. Показанные опубликованные примеры немедицинские.
LLM и оплата — mock, письма — Mailpit, хранение — local. MinIO для этого просмотра
не запускается: на этом этапе он не нужен. Полная инфраструктура по-прежнему
доступна через основной docker-compose.yml.

## Остановка и повторный запуск

Остановить с сохранением данных:

```sh
docker compose -f docker-compose.yml -f docker-compose.preview.yml down
```

Повторный запуск — `bash start-mac.command`. Не добавляйте `-v` к down,
если хотите сохранить ответы и созданный контент.

Если сайт не открывается:

```sh
docker compose -f docker-compose.yml -f docker-compose.preview.yml ps -a
docker compose -f docker-compose.yml -f docker-compose.preview.yml logs --tail 50 web migrate
```

Если Docker сообщает, что порт уже занят, остановите другое приложение,
использующее 3000, 5432, 1025 или 8025. Скрипт не останавливает чужие контейнеры.
При проблеме со сборкой сохраните вывод Terminal для диагностики.

## Дальнейшая работа в Codex

Откройте в настольном приложении или IDE папку `emil2` с этими файлами и попросите
продолжить по `AGENTS.md` и `docs/SPEC.md`. Готовы этапы 0–3; следующий продуктовый
этап — интервальное повторение. После изменения исходников запустите
`bash start-mac.command` повторно, чтобы пересобрать контейнер сайта.

## Проверка подготовки

Конфигурация проверена в облачной Linux-среде на новых томах с отдельными
портами: миграции и оба seed завершились успешно, health/каталог/бесплатный
урок ответили 200, запрос входа доставил письмо в локальный Mailpit.
Также проверены синтаксис bash и формат Compose. Запуск непосредственно
на физическом Mac ещё предстоит выполнить на вашем компьютере.

## Как получить обновлённую версию из ZIP

Скачайте свежий архив из ветки `codex/macos-local-preview` и распакуйте
в отдельную папку. Откройте Terminal в этой новой папке и запустите
`bash start-mac.command`. Обновится код контейнеров и применятся новые миграции;
данные остаются в прежних Docker-томах проекта `emil2-local-preview`.
После запуска обновите страницу браузера. Если вы вручную меняли `.env`,
сохраните нужные локальные настройки и для новой папки; рабочий `.env`
в архив не входит.
