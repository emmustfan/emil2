# Просмотр платформы под пользователем · этап 12Б

## Как открыть

1. Войдите администратором с подтверждённой почтой или Telegram.
2. Откройте «Пользователи» → карточку ученика или учителя. Кнопка
   **«Посмотреть как этот пользователь»** также есть в карточке прогресса.
3. Укажите причину: 5–500 символов. В окне есть предупреждение:
   «Режим только для просмотра. Вход будет записан в журнал».
4. Откроется кабинет выбранного пользователя. На всех страницах есть
   плашка с именем, отметкой «только просмотр», оставшимся временем и
   кнопкой **«Выйти»**. На телефоне плашка занимает собственное место;
   боковое меню начинается под ней.
5. «Выйти» возвращает в административную карточку этого пользователя.
   Там в блоке **«Просмотры администратором»** видны инициатор, время,
   продолжительность, причина и способ завершения.

В preview войдите как `owner@example.ru` через
http://localhost:3000/login. Письма — http://localhost:8025.
Откройте http://localhost:3000/admin/progress и карточку
`demo-student-01@example.ru` (также готовы 02 и 03).
Для проверки учителя выберите `teacher@example.ru` в «Пользователях».

## Права и срок

- Только действующий ADMIN с подтверждённым способом входа и актуальным
  согласием может начать просмотр. На каждом запросе заново проверяются
  его роль, блокировка, удаление и подтверждённый способ входа.
- Цель — USER или EDITOR, включая заблокированных. Другой ADMIN, сам
  инициатор, удалённый и обезличенный пользователь недоступны.
- Если у цели не приняты текущие согласия, виден её экран первого входа.
  Администратор не может принять согласия за неё.
- Блокировка цели сохраняется в БД. Только для подтверждённого режима
  разрешено читать её кабинет, повторение и закреплённый редактор.
  Роль и TeacherSubject проверяются по цели; платные уроки проверяются
  обычным `lib/access`, в том числе с учётом её блокировки.
- Одновременно у администратора один активный режим, включая запуск
  из разных браузеров. Параллельные старты сериализованы блокировкой.
- `admin.impersonationMinutes` в «Настройках»: по умолчанию 30 минут,
  допустимо 1–1440. `admin.impersonationHistoryLimit`: последние 50 записей
  в карточке, настраивается в пределах 1–100; полный журнал остаётся в БД.
- TTL проверяется сервером на каждом запросе. Открытая вкладка при
  истечении срока возвращает в административную карточку. Завершение
  журналируется при запросе, обнаружившем истечение; `endedAt` равен
  самому сроку окончания. После закрытия браузера запись об истечении
  появляется при следующем запросе администратора или следующем старте.

Обычный выход администратора из аккаунта в другом браузере завершает
его режимы с причиной `admin_logout`. В самом режиме сначала нажмите
«Выйти» на плашке; затем можно выйти из административного аккаунта.
Выход из аккаунта цели в режиме просмотра запрещён, как остальные изменения.

## Что запрещено

В режиме нельзя ответить на пропуск или тест, раскрыть/оценить карточку,
написать тьютору, оплатить или изменить подписку, сохранить редактор,
импортировать, изменить профиль/способ входа, принять согласие, удалить
аккаунт или начать ещё один режим.

Любой запрос к `/api/*`, кроме GET/HEAD/OPTIONS, получает 403 с сообщением
«Режим просмотра: изменения от имени пользователя запрещены».
Единственное исключение — POST `/api/admin/impersonation/stop`.
Интерфейс показывает ответ штатным способом ошибок. Проверка стоит в
`proxy.ts`, до разбора тела и до обработчика, и охватывает также новые
API-маршруты. Обычные запросы без режима проходят прежние проверки доступа.

Сессия администратора в `sid` сохраняется. Для режима используется отдельная
непрозрачная cookie: HttpOnly, SameSite=Strict, Secure в production/HTTPS.
В БД хранится только хэш токена. Cookie режима — браузерная сессия;
срок доступа определяет серверная `expiresAt`, а не срок cookie.
Без действующей сессии того же администратора токен не даёт доступа.
Сессии цели не создаются, не продлеваются и не меняют lastSeenAt.

`readOnly` поступает из проверки cookie на сервере. Параметры запроса,
тело и клиентские заголовки не могут включить этот признак. При передаче
actor в Prisma выбираются только userId/demoSessionId; служебный признак
не становится условием БД или сохраняемым полем.

RootLayout не подключает Метрику. Экспортируемый metrikaGoal дополнительно
игнорирует режим, включая очередь отложенных целей при просмотре уже
оплаченного платежа. DOM-отметка режима служит только аналитике;
серверные права по ней не определяются. Server Actions в текущем проекте
нет: изменения выполняются через API.

## Журнал и проверки

- `IMPERSONATION_STARTED`: причина, цель, id режима, срок.
- `IMPERSONATION_ENDED`: exit/expired/admin_logout/admin_revoked и длительность.
- `IMPERSONATION_WRITE_BLOCKED`: метод и pathname, без query, тела, cookies
  и токенов; не чаще раза в минуту на путь внутри одного режима. Ограничение
  защищено транзакционной блокировкой и действует при параллельных запросах.
- Для USER дополнительно StudentDataAccess(view="impersonation"); для EDITOR
  такой записи нет. Содержимое переписки не выгружается в журнал режима.

Unit: `tests/unit/impersonation.test.ts`. Интеграция жизненного цикла и
неизменности: `tests/integration/impersonation*.test.ts`. Все изменяющие
методы перечисляются через AST файлов маршрутов, без ручного списка.
E2E: `tests/e2e/impersonation.spec.ts` — ученик и учитель, desktop/mobile.
Снимки — `tmp/screenshots/impersonation-{chromium,mobile}.png`.

## Черновик для политики конфиденциальности

**НУЖНО СОГЛАСОВАНИЕ. Юридический документ не изменён.**

> Для разбора обращения администратор платформы может временно открыть
> интерфейс вашего аккаунта в режиме просмотра. В этом режиме ему доступны
> сведения и учебные материалы, доступные вашему аккаунту. Изменения от
> вашего имени запрещены. Причина, инициатор, время и продолжительность
> просмотра фиксируются во внутреннем журнале доступа. Администратор
> обязан использовать просмотр только для решения обращения или проверки
> работы платформы.

До использования текста в публичной политике нужно согласовать основание,
объём видимых сведений, круг администраторов, сроки хранения журнала и
процедуру рассмотрения обращений. Этот черновик сам не задаёт правовое основание.
