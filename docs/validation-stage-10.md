# Этап 10: локальная стабилизация и подготовка запуска

Работа выполнена в пределах согласованного локального MVP. Реальные сервисы,
публичный домен и боевые списания пользователь отложил. Поэтому приёмка HTTPS
на рабочем сервере, настоящего SMTP/S3/ИИ и оплаты/возврата 1 ₽ не заявляется.

## Качество и сценарии

- Проверены `lint`, `typecheck`, `format:check`, `git diff --check`, production
  build Next.js, синтаксис shell-скриптов, разбор production Compose и Caddy.
- **159 unit-тестов**: добавлены индексация preview/production, удаление
  личного контекста из мониторинга, отключение отправки в тестах, envelope и
  дедупликация, цены/неизвестный usage, heartbeat, версии S3 при удалении
  исходника, отказ восстановления в непустой/рабочий бакет, безопасная
  очистка только старых завершённых offsite-копий.
- **119 интеграционных сценариев**: 116 прежних и 3 новых проверки —
  неизменяемая анонимная оценка расходов, параллельные читатели с ожиданием
  писателя, sitemap без платных, непроверенных и неопубликованных материалов.
  Основной набор 118 прошёл вместе; дополнительная проверка sitemap и два
  новых сценария прошли отдельным повтором файла operations.
- Новый сквозной E2E прошёл на desktop и mobile: демо → письмо → согласие →
  закрытый урок → тестовая оплата → доступ → ошибка в уроке → карточка →
  повторение с новой датой. **Все 84 E2E-сценария прошли** на desktop/mobile Chromium (общий прогон — 8,1 минуты).

Находки при сборке исправлены до выпуска: сохранена исходная startup-валидация
ENV в instrumentation; Sentry hook ограничен Node runtime; добавлен metadataBase.
Типовые ошибки в новых тестовых импортах исправлены, проверка повторена.
Проверка migration-образа обнаружила закрытые права исходных файлов у root;
в migration target добавлен явный chown перед переходом к USER node.

## Нагрузка k6

Проверка на оптимизированной сборке Next.js в облаке, с mock-провайдерами и
PostgreSQL/pgvector. Три независимых веб-процесса за Caddy, отдельный worker.
Сценарий: рост 1 → 50 → **300 VU**, удержание 45 секунд, чтение лендинга и
синтетического бесплатного урока, health API, пауза чтения 5 секунд.
Общий прогон — около 95 секунд.

| Метрика         |        Результат |     Порог |
| --------------- | ---------------: | --------: |
| HTTP-запросов   |           10 699 |         — |
| Средняя частота | 113,18 запроса/с |         — |
| Ошибки HTTP     |      0 из 10 699 |      < 1% |
| p95 страниц     |        794,34 мс | < 2500 мс |
| p95 health API  |        153,80 мс |  < 300 мс |

Процесс k6 завершился кодом 0; измерения ниже заданных порогов; [структурированный результат](performance-stage-10.json). Важно для чтения исходного `--summary-export` k6 1.0.0: булевы значения
`metrics.*.thresholds` — флаги **нарушения** порога. `false` означает,
что порог не нарушен. Это проверено двумя изолированными контрольными запусками:
794 мс при `p(95)<2500` → exit 0 / flag false; 3000 мс → exit 99 / flag true.
В структурированном результате сохранены численные критерии, код завершения
и пояснение формата вместо неоднозначного общего boolean.

Это не браузерный LCP на 4G, не нагрузка
платёжного провайдера или ИИ и не обещание скорости любого выбранного VPS.
Квоты и защита доступа сохранены. Персонализированный HTML не кешировался.

Первый интенсивный прогон с одним процессом и паузой 1 секунду: ошибок 0%,
но p95 страниц около 4,70 с, health 1,69 с. Выявлена эксклюзивная блокировка
темы на чтении. После shared-lock ожидание публикации сохраняется, читатели
не блокируют друг друга. Два процесса и реалистичная пауза чтения дали
p95 страниц 1,38 с, health 439,55 мс; третий процесс позволил пройти оба порога.
Рабочая конфигурация рассчитана на три реплики web с ограничением памяти.

Первые сетевые попытки Docker k6/Caddy не достигали сервера из-за адреса
host-gateway и маршрутизации внутреннего HTTP через proxy. Эти попытки не
считались нагрузочной приёмкой. Для собственных локальных upstream настроен
NO_PROXY с сохранением внешнего proxy. В сценарий добавлена проверка готовности
до запуска VU и обработка отсутствующего тела ответа. Внешние запреты сети
не обходились.

## Бэкап и восстановление

На сохранённой preview-базе создана собственная немедицинская фикстура:
администратор, опубликованный учебный стенд, настоящее WebP-изображение,
ошибочный ответ, прогресс и карточка повторения. Сайт и worker локального
стенда приостановлены на время `pg_dump` и архива файлов и запущены снова.
Архив и SHA-256 сохранены с закрытыми правами в игнорируемом `tmp/backups/`.

`restore.sh` восстановил копию в **чистый PostgreSQL в отдельном контейнере**,
новую базу `emil2_restore_stage10` и отдельный uploads-том. Сравнены все поля
и строки таблиц User, Session, Subject, Topic, Gap, Question, GapAnswer,
TopicProgress, Card, Plan, Subscription, Payment, LegalDocument, TopicImage,
ImportJob и LlmUsage. Расхождений нет. Байты восстановленного изображения
совпали с исходным SHA-256. Текущая база не заменялась. Собственные фикстуры
на исходном стенде удалены; сохранённые копии и тома не удалялись.

Продакшн-передача в отдельный S3-бакет и восстановление файлов проверены
через заглушку AWS SDK. Настоящие бакеты/ключи не использовались; политики
14-дневного хранения только подготовлены как конфигурационные файлы.
Реальная offsite-копия и расписание требуют приёмки после подключения S3.

## Рабочий образ и эксплуатация

`Dockerfile.production` собирает Next.js и отдельные runtime-зависимости;
tsx перенесён в dependencies для worker и изолированного парсера. Runtime
работает от node (UID 1000), без записи в корневую файловую систему;
временные каталоги и Next cache задаются tmpfs. Migration target содержит
Prisma CLI, запускается отдельно от сайта. Оба target собраны. Секреты не
передавались в build. В изолированном контейнере без сети подтверждены UID 1000,
read-only root, работа sharp, tsx и PDF-парсера в дочернем процессе, локальные
opaque-файлы и загрузка сгенерированного Prisma Client. Production entrypoint
отказался запускать приложение с mock/log/local. Migration target проверен
на наличие Prisma CLI и всех миграций. Тест runtime выполнялся с явно
переопределённым entrypoint и mock-окружением, без запуска реальных адаптеров.

Production Compose разобран без запуска публичного домена: база не имеет
публикуемого порта, web доступен только через Caddy, X-Real-IP перезаписывается
прокси. Подготовлены health с heartbeat, Sentry/GlitchTip без личных данных,
анонимный LLM ledger, canonical/OG, robots/sitemap и закрытая индексация preview.

Инструкция владельцу и оператору — [runbook.md](runbook.md). Проверки внешнего
uptime, реальных алертов, DNS/HTTPS и боевого платежа остаются до отдельного
согласованного подключения сервисов. Техническая структурная проверка уроков
не заменяет медицинскую экспертизу.
