# Размещение «Эмали» на study.shkolaru.ru: с нуля

Это инструкция для владельца, который впервые запускает сайт. Команды ниже
вы выполняете сами на своём сервере. Подготовка проекта и этой инструкции
не создаёт сервер, DNS-записи или работающий сайт в интернете.

Используем **study.shkolaru.ru**. Основной адрес `shkolaru.ru` можно оставить
для существующего сайта. Если решите использовать другой поддомен, замените
его в DNS, двух полях конфигурации, Telegram и уведомлениях ЮKassa.

## 1. Что понадобится

| Что                                   | Для чего                                            |
| ------------------------------------- | --------------------------------------------------- |
| Доступ к управлению DNS `shkolaru.ru` | Связать адрес сайта с сервером                      |
| Новый VPS с Ubuntu 24.04 LTS          | Компьютер в дата-центре, который работает постоянно |
| IPv4-адрес и доступ SSH               | Подключаться к серверу из Терминала Mac             |
| Настоящая исходящая почта SMTP        | Доставлять ссылки для входа ученикам                |
| API для чата и embeddings             | Поиск по методичкам и ответы тьютора                |
| Два закрытых S3-бакета                | Изображения/импортированные файлы и резервные копии |
| Тестовый магазин ЮKassa               | Проверить оплату без реальных денег                 |

Для имеющейся конфигурации с тремя процессами сайта выбирайте **от 4 vCPU,
8 ГБ RAM и 80 ГБ SSD**, архитектура x86-64. Это стартовый ориентир, а не
обещание вместимости. Размещайте базу и хранилище в РФ согласно требованиям
проекта. Требования к обработке персональных данных и документы владельца
нужно согласовать перед приглашением настоящих учеников.

Инструкция рассчитана на **новый пустой сервер**, без панели управления,
другого сайта и Nginx на портах 80/443. VPS оплачивается отдельно от домена.
Конкретный тариф и поставщика выбираете вы; установщик Ubuntu у VPS должен
выдать IP и способ входа. Docker Desktop на Mac оставьте для локального просмотра.

Порядок работы: **сервер → DNS → ключи сервисов → конфигурация → сборка →
первый запуск → проверка → резервные копии**. Telegram и аналитика необязательны.
Подробные шаги подключения сервисов: [integrations-production.md](integrations-production.md).

## 2. Подключиться с Mac и установить Docker

Откройте приложение **Терминал** на Mac. Замените `IP_СЕРВЕРА` на IPv4 из
панели VPS, например четыре числа через точки; сам пример IP копировать не нужно:

```bash
ssh root@IP_СЕРВЕРА
```

Если провайдер выдал пользователя `ubuntu`, подключайтесь как `ubuntu`, затем
выполните `sudo -i`. При первом подключении сверьте отпечаток SSH с данными
провайдера и подтвердите подключение. Пароль при вводе не виден — это нормально.
Если провайдер использует SSH-ключ, выполните его инструкцию подключения.

Дальнейшие команды до слова «Mac» выполняются **внутри сервера**, в этом же окне.
Установите Docker из официального репозитория для Ubuntu:

```bash
apt-get update
apt-get install -y ca-certificates curl git nano openssl ufw
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
cat > /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "$VERSION_CODENAME")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
systemctl enable --now docker
docker compose version
```

Ожидается `Docker Compose version ...`, без ошибки. Исходная инструкция
Docker: <https://docs.docker.com/engine/install/ubuntu/>.

Создайте пользователя для работы с проектом:

```bash
adduser emal
usermod -aG sudo,docker emal
install -d -m 0755 -o emal -g emal /opt/emil2
```

`adduser` попросит придумать пароль. Необязательные сведения об имени можно
пропускать Enter. Пользователь из группы `docker` управляет серверными
контейнерами; это учётная запись владельца сервера, а не ученика сайта.

Откройте порты **сначала для SSH**, затем для сайта:

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 443/udp
ufw enable
ufw status
```

Это предполагает стандартный SSH-порт 22. Если провайдер дал другой порт,
разрешите именно его **до** `ufw enable`. Если у VPS есть отдельный сетевой
экран в панели, откройте те же порты и там. Порты базы 5432 и приложения 3000
открывать наружу не требуется.

Переключитесь в нового пользователя, чтобы применились группы:

```bash
su - emal
docker compose version
```

Не закрывайте первый рабочий SSH-сеанс, пока не проверите второй вход по
инструкции провайдера. Менять настройки SSH для выполнения этого руководства
не требуется.

## 3. Привязать поддомен

1. Откройте управление **DNS-зоной** `shkolaru.ru` там, где обслуживаются его
   DNS-серверы. Это может быть другой сервис, чем продавец домена.
2. Добавьте запись: **тип A**, **имя `study`**, **значение — IPv4 вашего VPS**.
   TTL оставьте по умолчанию. В некоторых панелях имя нужно вводить целиком:
   `study.shkolaru.ru`.
3. Записи `@`, `www`, MX и записи существующей почты сохраните.
4. Для `study` не должно быть другой конфликтующей A/CNAME-записи. AAAA
   добавляйте только при настроенном IPv6 VPS; старую AAAA этого поддомена,
   ведущую на другой сервер, исправьте или удалите.
5. Если панель предлагает проксирование/CDN, выберите **DNS only / только DNS**.
   Текущая конфигурация получает IP клиента напрямую через Caddy; дополнительный
   прокси требует отдельной настройки, в частности для уведомлений ЮKassa.

На **Mac в другом окне Терминала** проверьте:

```bash
dig +short study.shkolaru.ru A
dig +short study.shkolaru.ru AAAA
```

Первая команда должна показать IP вашего VPS. Вторая может ничего не вывести,
если IPv6 не используется. Изменения DNS иногда занимают несколько часов.
До запуска контейнеров сайт ещё не откроется.

## 4. Скачать актуальный проект на сервер

В серверном окне под пользователем `emal` выполните:

```bash
git clone --branch codex/macos-local-preview https://github.com/emmustfan/emil2.git /opt/emil2
cd /opt/emil2
git rev-parse HEAD
cp infra/production/env.example .env.production
chmod 600 .env.production
```

Здесь указана ветка с текущей реализацией. Не заменяйте её на `main`, пока
изменения не объединены туда. Если GitHub требует доступ к закрытому репозиторию,
используйте личный доступ или отдельный deploy key только для чтения;
не вставляйте токен в адрес `git clone`. Папка `/opt/emil2` должна быть пустой
перед первым клонированием.

`cp` выполняется **только при первом запуске**. При обновлениях сохраняйте уже
заполненный `.env.production`. Этот файл не включается в Git и ZIP проекта.

## 5. Заполнить конфигурацию

Сначала создайте случайный пароль базы:

```bash
openssl rand -hex 24
```

Сохраните полученную строку в менеджере паролей. Откройте файл:

```bash
nano .env.production
```

Замените значения следующих полей (угловые скобки — пояснения, их не оставляют):

```dotenv
SITE_DOMAIN=study.shkolaru.ru
APP_URL=https://study.shkolaru.ru
POSTGRES_PASSWORD=<сгенерированная строка>
DATABASE_URL=postgresql://app:<та же строка>@postgres:5432/dental
ADMIN_EMAILS=<ваша настоящая почта для входа администратором>
SUPPORT_EMAIL=<действующая почта поддержки>
LEGAL_ENTITY_NAME="<полное наименование владельца сервиса>"
LEGAL_ENTITY_INN=<его ИНН>
SITE_INDEXING=false
```

Пароль из `openssl rand -hex` состоит из безопасных для URL символов.
В `POSTGRES_PASSWORD` и `DATABASE_URL` он должен совпадать. Позднее замена
только этих строк не меняет пароль в уже созданной базе.

`ADMIN_EMAILS` — один или несколько адресов через запятую, без пробелов.
Используйте свой доступный ящик: вход придёт туда. Тестовые адреса
`owner@example.ru` для публичного сайта не подходят. При первом входе адрес
из этого списка получает роль администратора; учителей затем назначают в
«Пользователи» и закрепляют за предметами.

Заполните блоки **SMTP, LLM, S3, BACKUP_S3 и тестовой ЮKassa** по
[следующей инструкции](integrations-production.md). Остальные исходные
параметры оставьте, включая `NODE_ENV=production`, `TRUST_PROXY=true`,
`EMBEDDING_DIM=1536` и `YOOKASSA_TEST_MODE=true`. Необязательные Telegram,
Метрика и Sentry могут остаться пустыми.

Чтобы сохранить в nano: **Ctrl+O → Enter → Ctrl+X**. На Mac это Control,
а не Command. Ключи, пароли и сам `.env.production` никому в чат не отправляйте.
В менеджере паролей сохраните также копию конфигурации: резервная копия
базы не содержит этого файла.

Рабочая конфигурация специально отклоняет `mock`, почту `log` и локальное
хранилище. Настоящие подключения нужны до запуска production; локальный
просмотр на Mac продолжает работать без них. Надпись «настроено» в админке
означает наличие параметров, а фактическую работу проверяют отдельным сценарием.

## 6. Собрать и запустить

Все команды — на сервере, из `/opt/emil2`. Первая сборка может занять
несколько минут:

```bash
docker compose --env-file .env.production -f docker-compose.production.yml build web migrate
```

Проверьте конфигурацию **до создания базы**:

```bash
docker compose --env-file .env.production -f docker-compose.production.yml run --rm --no-deps --entrypoint node web --import tsx scripts/ops/preflight.ts
```

Успех — `production_configuration_valid`. Это проверка заполнения и
совместимости параметров, без проверки связи с поставщиками. При ошибке
исправьте названное поле в nano и повторите. Не выводите весь `docker compose
config` в общий чат: он раскрывает секреты.

Следующие команды создают **новую базу на VPS**. Данные с Mac автоматически
не переносятся. Если они нужны, сначала прочитайте раздел 11 ниже.

```bash
docker compose --env-file .env.production -f docker-compose.production.yml up -d postgres
docker compose --env-file .env.production -f docker-compose.production.yml run --rm migrate
```

Миграции должны завершиться без ошибки; демонстрационные медицинские материалы
создаются черновиками и требуют эксперта. **После следующей команды сайт
станет доступен в интернете** по настроенному поддомену:

```bash
docker compose --env-file .env.production -f docker-compose.production.yml up -d web worker caddy
docker compose --env-file .env.production -f docker-compose.production.yml ps
```

Caddy сам получает и продлевает HTTPS-сертификат. Для этого DNS должен уже
вести на VPS, а порты 80/443 быть доступны извне. Покупать сертификат отдельно
не нужно. Сайт и фоновый worker запускаются вместе: без heartbeat worker
проверка готовности сайта не проходит. На первом запуске подождите 1–3 минуты.

```bash
curl -f https://study.shkolaru.ru/api/health
```

Команда должна закончиться без ошибки, а `ps` показывать здоровые процессы
`web`, работающие `worker`, `postgres`, `caddy`. Откройте в браузере
**https://study.shkolaru.ru**. `SITE_INDEXING=false` запрещает индексацию
поисковикам, но не закрывает сайт паролем.

## 7. Пройти первый запуск как владелец

1. На `/login` укажите почту из `ADMIN_EMAILS`. Откройте письмо **в том же
   браузере**, где запросили ссылку, и подтвердите вход. Здесь используется
   одноразовая ссылка, парольный вход пока не реализован.
2. Заполните профиль. Убедитесь, что открывается `/admin`.
3. Откройте «Настройки»: проверьте реальные контакты, юридические документы,
   тексты лендинга, цены, лимиты и тарифы. Шаблонные документы не являются
   готовыми документами вашего бизнеса.
4. В «Предметы и уроки» откройте предмет → **«Открыть книгу и редактор уроков»**.
   В дереве добавьте раздел и урок. Подробная [инструкция автора](lesson-authoring.md).
5. Проверьте текст, картинку, пропуск, тест, автора, рецензента и источники.
   До экспертной проверки медицинские черновики ученикам не публикуйте.
6. Подтверждённый бесплатный урок проверьте в отдельном браузере как ученик:
   доступны ответы и сохранение прогресса, а админка недоступна.
7. Назначьте отдельному аккаунту роль учителя и один предмет. Учитель должен
   редактировать материалы этого предмета и получать отказ в чужих.
8. Проверьте реальное письмо, загрузку изображения, ответ тьютора с источником
   и тестовую покупку по сценариям [интеграций](integrations-production.md).

Регистрационные письма уходят настоящим получателям. Приглашайте первые
тестовые аккаунты сами. Для смены роли используйте отдельный браузерный
профиль или выход из аккаунта: роль определяется сервером, переключателя
«стать администратором» у ученика нет.

## 8. Настроить резервные копии

Сначала создайте и настройте второй закрытый S3-бакет по инструкции интеграций.
На сервере выполните:

```bash
sudo install -d -m 0700 /var/backups/emil2
sudo env EMIL2_BACKUP_DIR=/var/backups/emil2 bash scripts/ops/backup.sh production
```

Успех — сообщение «Копия создана», а в backup-бакете есть соответствующая
папка с **`COMPLETE.json`**. Копия сохраняет базу, список и версии файлов;
пустая папка или частичная загрузка копией не считается.

Включите ежедневное расписание:

```bash
sudo cp infra/production/emil2-backup.service /etc/systemd/system/
sudo cp infra/production/emil2-backup.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now emil2-backup.timer
sudo systemctl list-timers emil2-backup.timer
```

Файлы рассчитаны на путь `/opt/emil2`. Копирование запускается примерно
в 03:15 UTC с небольшим случайным сдвигом. Проверка последнего запуска:

```bash
sudo journalctl -u emil2-backup.service -n 50 --no-pager
```

Настройте уведомления о сбое задания в мониторинге VPS и храните доступ
к резервному бакету отдельно от сервера. Срок хранения копий — 14 дней
при применённой политике бакета. Периодически проверяйте восстановление в
отдельную базу по [runbook.md](runbook.md), а не поверх рабочего сайта.

## 9. Как обновлять сайт

Войдите на сервер, перейдите в проект и сначала сделайте копию:

```bash
cd /opt/emil2
sudo env EMIL2_BACKUP_DIR=/var/backups/emil2 bash scripts/ops/backup.sh production
git rev-parse HEAD
git pull --ff-only origin codex/macos-local-preview
docker compose --env-file .env.production -f docker-compose.production.yml build web migrate
docker compose --env-file .env.production -f docker-compose.production.yml run --rm migrate
docker compose --env-file .env.production -f docker-compose.production.yml up -d web worker caddy
curl -f https://study.shkolaru.ru/api/health
```

Продолжайте только после успешной копии. Сохраните прежний номер коммита:
он помогает разбирать обновление. Уже применённые миграции повторно не
выполняются, seed не должен перезаписывать созданные вами уроки. Если
обновление требует специального порядка миграций, следуйте его инструкции.

Если изменили `.env.production`, повторите проверку `preflight` из раздела 6
и команду `up -d web worker caddy`: простого `restart` недостаточно для
применения новых переменных. Не заменяйте заполненный файл шаблоном.

**Не выполняйте `down -v`, `db:reset` или удаление Docker-томов:** там база.
Откат кода не отменяет миграции и платежи; аварийное восстановление описано
в runbook и выполняется через отдельную базу с проверкой.

## 10. Если что-то не заработало

Начните с безопасных команд в `/opt/emil2`:

```bash
docker compose --env-file .env.production -f docker-compose.production.yml ps
docker compose --env-file .env.production -f docker-compose.production.yml logs --no-color --tail=80 web worker caddy
```

| Симптом                        | Что проверить                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------- |
| Адрес не открывается           | A/AAAA поддомена, IP VPS, порты 80/443 и сетевой экран провайдера                                 |
| Ошибка сертификата             | DNS уже обновился; `caddy` работает; другой сервис не занимает порты                              |
| 503 / unhealthy                | Логи `web` и `worker`, применение миграций, heartbeat worker, параметры БД                        |
| Ошибка `Invalid environment`   | Названное поле в `.env.production`; необязательный ID Метрики оставьте пустым, а не текстом       |
| Письма не приходят             | SMTP-логин, пароль, порт, отправитель, SPF/DKIM, папка «Спам», доступность SMTP из VPS            |
| Картинки не загружаются        | Закрытый S3-бакет, endpoint/region, права ключа, тип и размер файла                               |
| Тьютор не находит материал     | Урок опубликован и проверен, worker построил embeddings размерности 1536, тарифный лимит доступен |
| Тестовый платёж не подтверждён | Webhook URL и события, IP-список ЮKassa, DNS без прокси, тестовые ключи                           |

При обращении за помощью отправляйте текст ошибки и статус процессов,
предварительно убрав адреса пользователей и одноразовые ссылки. Файлы `.env`,
ключи и полные настройки контейнеров не нужны.

## 11. Что будет с уроками на Mac

Новый VPS начинает с новой базы; локальные уроки и изображения остаются на Mac.
Если локальная версия была только тренировкой, переносить её не обязательно.

Если там уже ваши рабочие материалы, **до первого запуска миграций/seed на
VPS** сделайте на Mac `bash backup-mac.command`. Папка копии содержит
`database.dump`, `uploads.tar`, `FORMAT`, `SHA256SUMS`. Сохраните её целиком.
Это конфиденциальные данные, не прикладывайте их в публичный GitHub.

Перенос состоит из **двух частей**: PostgreSQL и файлы. Загрузка ZIP проекта
или одного дампа не переносит изображения в S3. Для оператора перенос на
свежую базу выполняется так:

1. Проверить SHA-256 и формат копии, безопасно проверить архив через
   `scripts/ops/check-archive.ts` (см. runbook).
2. Восстановить дамп PostgreSQL 16 только в пустую базу, без `--clean` и
   удаления данных. Если база уже заполнена — использовать отдельную базу
   через процедуру восстановления из runbook.
3. Перенести файлы из `uploads.tar` в закрытый рабочий S3-бакет **с теми же
   именами ключей в корне бакета**, без дополнительной папки. Не менять имена
   и не включать публичный доступ: ссылки в базе опираются на эти ключи.
4. Применить только `pnpm db:migrate` из сервиса `migrate` к восстановленной
   базе; оценить необходимость seed отдельно. Проверить изображения, импорт,
   права, уроки и тарифы; оставить ЮKassa в тестовом режиме.

Для непустой базы не выбирайте произвольное новое имя только в `DATABASE_URL`:
скрипт резервного копирования ориентируется также на `POSTGRES_DB` сервиса
PostgreSQL. Переключение базы и схемы резервного копирования должно быть
согласованным. Если нужны реальные материалы с Mac, перед публичным запуском
передайте эту часть оператору вместе с [процедурой восстановления](runbook.md).
Исходную локальную копию храните до полной проверки переноса.
