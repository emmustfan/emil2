## HTTP-аудит режима

Интеграционный тест поднимает отдельный локальный Next.js на свободном
порту, использует PostgreSQL и настоящие обработчики. Перед снимком через
HTTP создаются ответ на пропуск, прогон/ответ теста, раскрытие и оценка
карточки. В фикстуре есть ожидающий платеж, просроченное RUNNING-сообщение
и сессии цели со старым lastSeenAt.

Из исходников автоматически получены **39 файлов API-маршрутов** и
**37 шаблонов серверных страниц**. Для USER и EDITOR выполнены:

- **60** проверок изменяющих методов: везде 403, кроме отдельной проверки
  POST stop (303). Тело запроса не попало в журнал.
- **44** GET-запроса: все 14 обработчиков и все девять вариантов catch-all
  редактора. Административные данные USER/EDITOR недоступны.
- **72** открытия страниц. Две чужие платёжные страницы не открываются
  под учителем, у которого нет соответствующего платежа; их код отдельно
  проверен на чтение сохранённого состояния без refresh.
- Дополнительно **14** открытий под заблокированными USER/EDITOR:
  кабинет/профиль, повторение/очередь, квота тьютора, урок, кабинет учителя,
  закреплённый редактор и его API. blockedAt не меняется; обычная сессия
  заблокированной цели по-прежнему перенаправляется ко входу.

До и после обходов и выхода сравниваются количество и контрольная сумма
всех строк 20 таблиц: User, Session, TopicProgress, GapAnswer, GapAttempt,
Card, ReviewLog, TestRun, QuestionAttempt, UsageCounter, Event,
TutorConversation, TutorMessage, Payment, Subscription, Topic, Question,
Gap, TopicRevision, TeacherSubject. Все строки и даты сохраняются.
Предусмотренные записи режима — только ImpersonationSession, SecurityAudit
и StudentDataAccess. Детальный список мест чтения — [impersonation.md](impersonation.md).

Артефакт выполнения — `tmp/stage12b-http-audit.json`; серверные диагностические
логи — `tmp/impersonation-http-*.log`. Это локальные игнорируемые артефакты.
Тест удаляет только свои фикстуры и останавливает собственный HTTP-процесс.

## Сессии и права

Интеграция проверяет обязательную причину, подтверждённого ADMIN,
запрет другого ADMIN/самого себя/удалённой/обезличенной цели, одновременные
старты, подстановку cookie с другой сессией, readOnly actor, срок,
повторный выход без дубля, logout администратора, понижение/блокировку
инициатора и ограничение частоты WRITE_BLOCKED при параллельных запросах.
Правильные ответы на нерешённые задания не раскрываются; цель не получает
сессию, а sid администратора сохраняется.

Начало/завершение и попытки изменений видны в SecurityAudit; USER получает
StudentDataAccess(view="impersonation"), EDITOR — нет. История доступна
только ADMIN. Юридический текст подготовлен как черновик с пометкой
НУЖНО СОГЛАСОВАНИЕ; LegalDocument не изменяется.

Compose, start-mac.command и .env.example не менялись. Порядок запуска
сохраняется, миграция применяется штатным preview-стартером. Повторная
сборка чистой Docker-инфраструктуры для этих файлов не требуется.
