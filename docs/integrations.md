# Подключение сервисов: инструкция владельцу

Сначала откройте **«Интеграции»** в админке: `/admin/integrations`.
Страница показывает текущие режимы и объясняет шаги. «Настройки заданы»
означает только наличие конфигурации, а не успешную проверку связи.
Значения секретных ключей на странице не показываются.

## Что нужно прямо сейчас

Для создания уроков и обычной проверки ответов никакие внешние сервисы
не обязательны. Можно работать на Mac, пользоваться Mailpit и тестовым ИИ.
Парольный вход пока не реализован: одна и та же ссылка на почту используется
для первого и повторного входа. При повторном входе новая регистрация не нужна.

| Сервис            | Для чего                                     | Что нужно владельцу                                                |
| ----------------- | -------------------------------------------- | ------------------------------------------------------------------ |
| Почта             | Одноразовые ссылки входа и письма о подписке | SMTP-сервис и адрес отправителя                                    |
| Telegram          | Альтернативное подтверждение входа           | Бот, его секретный токен и домен сайта                             |
| Чат-модель ИИ     | Ответы тьютора и объяснения                  | Провайдер, API-ключ, адрес API и имя модели                        |
| Модель embeddings | Поиск фрагментов методички для тьютора       | Поддерживаемая модель с размерностью 1536                          |
| Хранилище файлов  | Изображения и будущий импорт                 | На Mac — Docker-том; перед запуском нужен рабочий файловый адаптер |

## Где записывать настройки

Ключи — это секретные данные сервера. Их не вставляют в текст урока,
обычную форму настройки тарифов, GitHub или этот чат.

1. Один раз запустите `bash start-mac.command`. Рядом с ним появится `.env`.
2. Откройте Terminal в этой папке проекта.
3. Выполните `nano .env`.
4. Найдите нужные строки и замените значения. Не добавляйте кавычки из примеров
   вокруг всего файла и не удаляйте остальные настройки.
5. Сохраните: **Ctrl+O**, затем **Enter**. Выйдите: **Ctrl+X**.
   Используется Control, не Command; в Ctrl+O — буква O.

Файл не входит в ZIP. При обновлении проекта переносите свой `.env` отдельно.
Не отправляйте его другим людям: внутри могут находиться секреты.

## Важно: обычный Mac-просмотр специально оставляет моки

`start-mac.command` принудительно включает тестовые LLM/платежи, Mailpit и
отключает Telegram. Поэтому просто заполнить ключ и повторить эту команду
недостаточно для настоящего ИИ.

После заполнения `.env` для ИИ/Telegram используйте отдельный запуск:

```sh
docker compose -p emil2-local-preview \
  -f docker-compose.yml -f docker-compose.preview.yml \
  -f docker-compose.integrations.yml up --build -d web worker
```

Он использует ту же базу и Docker-тома. Оплата останется mock, письма — Mailpit,
файлы — local. Дополнительный файл меняет только настройки ИИ/Telegram и адрес
сайта для web/worker. Если ключи не заполнены и LLM_PROVIDER=mock, внешних
запросов ИИ не будет. Повторный обычный `start-mac.command` вернёт моки.

## Подключить ИИ

Сначала нужен выбранный провайдер. Не любой чат в браузере предоставляет API,
и подписка на чат не обязательно включает оплату API.

Для **OpenAI-совместимого API** нужны поля:

```dotenv
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=АДРЕС_API_ОТ_ПРОВАЙДЕРА
LLM_API_KEY=ВАШ_СЕКРЕТНЫЙ_API_КЛЮЧ
LLM_CHAT_MODEL=ИМЯ_ЧАТ_МОДЕЛИ
LLM_EMBEDDING_MODEL=ИМЯ_МОДЕЛИ_ПОИСКА
EMBEDDING_DIM=1536
```

Это обозначения для замены, не готовые работающие значения. Сервис должен
поддерживать `/chat/completions` с потоковым ответом и `/embeddings`.
Адрес обычно включает путь API, например `/v1`. Чат-модель и embeddings-модель
могут иметь разные имена. Не меняйте размерность базы: для другой размерности
нужна миграция, а не только новая строка `.env`.

Для **Anthropic** задаются `LLM_PROVIDER=anthropic`, `LLM_API_KEY`,
`LLM_CHAT_MODEL`. Поиск подключается отдельно: `LLM_EMBEDDING_BASE_URL`,
`LLM_EMBEDDING_API_KEY`, `LLM_EMBEDDING_MODEL`, поскольку сам Anthropic
не предоставляет этот endpoint embeddings. Адрес поиска должен быть совместим
с API, который поддерживает приложение.

После запуска с дополнительным файлом:

1. Откройте «Интеграции»: вместо тестовой модели будет показана конфигурация
   провайдера. Это пока не проверка связи.
2. Дайте worker время подготовить опубликованные проверенные темы для поиска.
   После смены модели/адреса он переиндексирует их при запуске.
3. Откройте бесплатный урок и задайте вопрос, ответ на который есть в его тексте.
   Проверьте смысл ответа и сноски: они должны вести к реальным фрагментам.
4. Задайте вопрос вне материала и попробуйте объяснение неправильного ответа.
5. Отдельно проверьте медицинскую точность с преподавателем. Подключение API
   само по себе не подтверждает качество модели.

Вызовы настоящего ИИ оплачиваются по условиям провайдера. Дневные пользовательские
лимиты меняются в «Настройки → Тарифы». Вопросы и ответы по умолчанию сохраняются
в логах приложения. Перед рабочим запуском согласуйте провайдера и обработку
данных. В облачной разработке реальные API не вызывались, ключи не использовались.

## Подключить Telegram-вход

1. В Telegram откройте официальный `@BotFather` и выполните `/newbot`.
2. Следуйте его шагам: название и уникальное имя бота, заканчивающееся на `bot`.
3. Полученный токен запишите в `.env` как `TELEGRAM_BOT_TOKEN`.
   Имя без `@` — в `TELEGRAM_BOT_USERNAME`.
4. Для настоящего входа понадобится доступный домен сайта. В BotFather выполните
   `/setdomain`, выберите своего бота и укажите домен.
5. `APP_URL` должен совпадать с адресом сайта, на рабочем сервере — с HTTPS.
   Это также определяет адреса ссылок в письмах.
6. Перезапустите web/worker с выбранной конфигурацией и проверьте вход на домене.

Важное различие: наличие токена на Mac не делает `localhost` готовым доменом
для реального Telegram Login. Если домена пока нет, оставьте рабочий вход
по почте и настройте Telegram при подготовке публикации. Сайт в этой задаче
не публикуется и публичный адрес автоматически не создаётся.

Telegram здесь подтверждает личность. Он не проверяет задания и не подтверждает
знания. Напоминания в Telegram и отдельный учебный бот — другие функции,
они пока не подключены.

## Настоящая почта

Mailpit на `http://localhost:8025` — локальный просмотр писем. Письма из него
не приходят в Gmail, Яндекс.Почту и другие настоящие ящики.

Для рабочего сайта почтовый сервис выдаст SMTP-host, порт, логин, пароль и
разрешённый адрес отправителя. Нужны `MAIL_TRANSPORT=smtp`, `SMTP_HOST`,
`SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`. Отправитель и домен
настраиваются у этого сервиса. В production используйте основную конфигурацию
развёртывания: preview-файлы намеренно сохраняют Mailpit.

## Что с промптами

- Проверка вариантов и короткого ответа — обычное сравнение с эталоном автора.
  Вы заполняете правильные ответы и объяснения в конструкторе; промпт не нужен.
- Для дополнительной рецензии урока в редакторе есть готовый запрос с его текстом
  и эталонами. Его можно скопировать в выбранный ИИ-сервис. Автоматического
  вызова или автоматической экспертной отметки здесь нет.
- Инструкции тьютора уже заданы в `lib/tutor/prompts.ts`; вам не нужно вводить
  их для каждого вопроса ученика. Отдельного редактора этих системных правил
  в админке пока нет. Их изменение — задача разработки с проверкой ответов.
- Промпт проверки урока — `lib/content/review-prompt.ts`. Пользователь может
  дополнить скопированный текст, не меняя код платформы.
- Импорт PDF/DOCX/текста доступен в «Импорт материалов». Промпт уже задан в
  `lib/imports/draft.ts`; результат всегда сохраняется как непроверенный черновик.
  В локальном режиме тестовый ИИ показывает только технический пример.
  Подключение реальной модели используется и тьютором, и импортом.

Практический порядок сейчас: сначала отработать создание и экспертную проверку
уроков, затем выбрать провайдера и проверить настоящего тьютора на этих материалах.
