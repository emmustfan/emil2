# Импорт учебных материалов

Импорт доступен администратору и преподавателю. Преподаватель видит только
закреплённые за ним предметы. Откройте предмет → «Создать урок из PDF, Word
или текста» → вкладку «Из файла PDF / DOCX». При создании обычного урока эта
вкладка находится рядом с «Написать урок». В редакторе существующего урока
есть раскрывающийся блок «Импорт PDF/DOCX в этом предмете». Импорт создаёт
новые черновики и не заменяет текущий текст. Отдельного пункта импорта в
боковом меню нет; прежний адрес `/admin/imports` сохранён для старых ссылок.

1. Предмет уже выбран по открытому уроку или предмету. При необходимости
   выберите раздел.
2. Загрузите PDF с текстовым слоем, DOCX или TXT в UTF-8, либо вставьте текст.
   Максимальный файл — 20 МБ, извлечённый текст — 60 000 символов. Длинные
   материалы лучше загружать отдельными главами.
3. Удалите данные пациентов и другие персональные сведения. Подтвердите,
   что у вас есть права на материал. Название файла и профиль преподавателя
   не передаются модели; известные форматы персональных данных в тексте
   дополнительно скрываются, но это не заменяет ручную проверку исходника.
4. Нажмите «Создать черновики». Можно уйти со страницы и вернуться позже:
   задание записано в PostgreSQL, его выполняет отдельный процесс worker.
5. Дождитесь статуса «Черновики готовы» и откройте каждую тему. Импорт готовит
   15–30 пропусков, 10 вопросов с объяснениями и блоками-источниками, в том
   числе 3 диагностических. Длинный источник разделяется около заголовков
   или границ абзацев; за одну загрузку создаётся до 5 тем.
6. Отредактируйте формулировки и дистракторы, проверьте каждый ответ,
   укажите автора, рецензента и полное библиографическое описание. Поставьте
   «Проверено экспертом», отправьте на проверку и опубликуйте обычным способом.

Результат всегда `DRAFT`, `aiGenerated=true`, `needsExpertReview=true`.
Импорт не публикует материалы и не ставит экспертную отметку. Технический
валидатор проверяет разметку и структуру заданий; медицинскую точность
проверяет человек. Изображения из исходного документа не переносятся:
их можно добавить в редакторе урока после импорта.

## Тестовый и настоящий ИИ

Обычный запуск на Mac включает `LLM_PROVIDER=mock`. Он показывает весь путь
от загрузки до редактора без оплаты внешних запросов. Результат явно назван
«Технический черновик — тестовый ИИ»: это примеры упражнений по исходному
тексту для проверки интерфейса, которые преподаватель должен переработать.
Не оценивайте качество будущей медицинской генерации по этому режиму.

Реальная модель подключается позже по [инструкции интеграций](integrations.md).
Тьютор и импорт используют один выбранный провайдер, но разные системные
инструкции. Промпт импорта уже находится в `lib/imports/draft.ts`; для каждого
файла вручную его писать не нужно. Расходы реального провайдера зависят
от размера источника и числа частей. Невалидный JSON исправляется одним
дополнительным запросом; после второй ошибки темы не создаются.

## Ошибки и очередь

- «Нужен файл с текстом»: скан без текстового слоя, защищённый, повреждённый
  или слишком сложный документ. Экспортируйте обычный текстовый PDF/DOCX
  или вставьте текст вручную. OCR пока не входит в MVP.
- Ошибка генерации: проверьте источник и параметры модели, загрузите меньшую
  часть. Частично готовые темы не сохраняются — можно безопасно повторить.
- «В очереди» долго не меняется: должен работать `worker`. При обычном
  запуске Mac он запускается вместе с сайтом. Проверить:

  ```bash
  docker compose -p emil2-local-preview -f docker-compose.yml -f docker-compose.preview.yml logs --tail=50 worker
  ```

- Достигнут лимит: дождитесь текущих заданий. По умолчанию разрешены два
  одновременных импорта одного автора; по умолчанию не более пяти загрузок за час.
- Администратор снял назначение или заблокировал автора: обработка не создаст
  темы. Загрузить материал заново должен сотрудник с действующими правами.

При перезапуске worker незавершённое задание восстанавливается после истечения
его 15-минутной аренды. Повторная доставка задания не создаёт дубликаты тем.
После двух аварийных запусков требуется новая загрузка.

Исходный файл хранится по закрытому непрозрачному ключу: в локальном Docker-томе
для просмотра или в закрытом S3-бакете рабочего окружения. После завершения или
ошибки файл удаляется; если хранилище временно недоступно, worker повторяет
удаление. В журнале остаются статус и ссылки на черновики, без исходного файла.
Секреты S3 задаются только через переменные окружения, не в форме импорта.

Продуктовые ограничения `import.*` меняются администратором в «Настройках»
в пределах безопасных границ. Размер распакованного DOCX ограничен 8 МБ;
PDF — 200 страниц. Парсер работает отдельным процессом с ограничением
времени и памяти. Реальные S3 и LLM в облачных тестах не вызываются.
