## Проверить вручную на Mac

1. Обновите ZIP ветки `codex/macos-local-preview`, распакуйте в новую папку
   и запустите `bash start-mac.command`, как раньше. Docker сохраняет свою базу.
2. На `http://localhost:3000` попробуйте два задания и карточку в блоке примера.
   После обновления этот пример сбрасывается и не записывается в прогресс.
3. Нажмите «Попробовать бесплатно». Выберите цель и предмет
   «Знакомство с обучением». Пройдите три диагностических вопроса из разных тем.
4. Посмотрите результат, откройте урок, заполните три пропуска. Можно также
   пройти обычный тест урока и задать вопрос тьютору. В локальном просмотре тьютор — mock.
5. Нажмите «Дальше — попробовать повторение», откройте ответ каждой карточки
   и оцените сложность. Даты рассчитывает тот же schedule, что в обычном повторении.
6. Сохраните прогресс: запросите письмо, откройте ссылку из Mailpit в том же
   браузере, подтвердите вход и согласие. В кабинете будут цель, диагностика,
   ответы урока и карточки с назначенными датами.
7. Обновите страницу урока — ответы остаются. Повторный вход не создаёт копии.
   В существующем аккаунте его прежний первый ответ и расписание карточки имеют приоритет.
8. Отдельно попробуйте «Пропустить — просто покажите урок». Диагностика не
   создаётся; можно перейти к финалу без ответов и без искусственных карточек.

Исходные медицинские seed-темы остаются DRAFT/needsExpertReview. Для обычного
предмета демо доступно после публикации проверенной бесплатной темы и минимум
трёх диагностических вопросов в разных опубликованных проверенных темах.
Редактор отмечает вопрос для диагностики в конструкторе вопросов.

## Хранение и безопасность

- HttpOnly demo_sid использует тот же гостевой контекст, что урок и тьютор;
  lesson_guest оставлен совместимым псевдонимом. Сервер хранит хеш, а не cookie.
  Срок гостевого контекста — lesson.guestDays. anon_id живёт год.
- Переходы контролирует сервер. Вопросы/версии закрепляются один раз, ответы
  неизменяемы; диагностика раскрывает только верно/неверно и названия тем.
  Чужие карточки, перескок шагов, устаревшая версия и POST с чужим Origin отклоняются.
- Перенос GapAnswer/TestRun/Card/TutorConversation и пересчёт TopicProgress
  выполняются одной транзакцией после согласия. Claim одноразовый; старые
  запросы гостя больше не могут изменить перенесённые данные.
- Незавершённый ответ тьютора отменяется с возвратом старой гостевой квоты;
  завершённая переписка остаётся доступной новому владельцу. Пользовательская
  дневная квота начинается по обычным правилам, гостевой лимит не суммируется с ней.
- При совпадении карточки сохраняется расписание пользователя, а журналы демо
  присоединяются к ней с nullable cardRevision без конфликтов идемпотентности.
- Добавочная миграция сохраняет старые аккаунты, роли, сессии и историю.
  Event.userId теперь SET NULL при физическом удалении аккаунта, чтобы агрегаты
  не мешали будущему обезличиванию. Обычное управление аккаунтами — мягкое удаление.

## Аналитика

Все шаги демо пишут Event на сервере; повторы запросов не дублируют конверсии.
Также записываются открытия тем/paywall, первые ответы, завершения тестов,
вопросы тьютору/достижение лимита, окончания повторений и завершение регистрации.
Для клиентского POST разрешены только landing_viewed и review_session_completed;
число повторений сервер считает по собственному журналу текущего пользователя.
Конверсии демо и регистрации клиент создать не может. Есть Origin и rate limit.

first_touch сохраняет UTM первого визита на 30 дней и только hostname внешнего
referrer, затем переносится в User.utm. Неизвестные параметры, полные referrer URL,
email-подобные значения, токены из URL не принимаются. Пустой первый визит также
не заменяется рекламной меткой из следующего перехода. Данные цели и диагностики
сохраняются в профиле; события не содержат текст произвольной цели и ответов.

`YANDEX_METRIKA_ID` необязателен. Без него внешнего скрипта и баннера нет.
При настройке ID скрипт появляется только после явного разрешения в баннере.
Выбор можно изменить через «Настройки аналитики». Webvisor/clickmap/trackLinks
выключены везде. На login/auth/onboarding/cabinet/student/teacher/admin/learn/review/tutor
Метрика не загружается; при переходе туда активный счётчик уничтожается.
Внешние hit содержат только origin/path, цели — только разрешённые названия,
без внутренних ID, имени, почты, параметров адреса и содержимого форм.
Цель signup_completed отложена до следующей публичной страницы с разрешённой
аналитикой; собственный Event записывается сразу после согласия.

Лендинг читает LandingContent `landing.v1` (включая FAQ и примеры), опубликованные
предметы и Plan. Seed создаёт новые настройки, не перезаписывая существующие.
Редактор тарифов/лендинга относится к оставшейся части этапа 8.
Доступны title/description/OpenGraph/canonical и безопасная JSON-LD разметка
Organization, Course для опубликованных предметов, FAQPage. Реквизиты и отзывы
не выдумывались; ссылка поддержки появляется только при заданном SUPPORT_EMAIL.
